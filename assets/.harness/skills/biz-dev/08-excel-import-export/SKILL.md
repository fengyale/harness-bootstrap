# 表格导入与导出

> 定位：**同步还是异步、怎么流式读写、导入失败怎么报、临时文件怎么清**。临时文件落位与目录约定在
> `.harness/rules/工程结构.md`；本文只讲做法。项目里的表格库与上限在下方「项目绑定」。

## 何时用

- 需要让使用者批量导入数据，且数据可能不干净
- 导出结果可达数万行以上，页面同步等待会超时
- 已有导入只回一句"导入失败"，无法定位是哪一行出错

## 核心规则（跨技术栈不变）

1. **模板先行**：表头顺序、必填列、示例值、模板版本，一次定清
2. **一律流式读写**，内存占用不随行数增长
3. **先校验表头与版本**，不匹配整体拒绝，不进入逐行解析
4. **错误按行收集**，不抛第一个错就中断，报告中带行号与列名
5. **失败策略二选一并写进契约**：整批回滚，或部分成功加错误报告
6. **临时文件成功与失败路径都清理**，异常退出靠定时任务兜底

## Step 1 · 同步导出还是异步任务

| 行数 / 耗时 | 使用场景 | 做法 |
| --- | --- | --- |
| 万行以内且分钟级内完成 | 用户点完就等 | 同步流式导出，边取数边写响应 |
| 数万至数十万行 | 允许等待 | 异步任务：生成文件落盘，返回下载链接 |
| 百万行以上 | 任意 | 异步 + 分片生成 + 分片或断点下载 |
| 导入超过单次行数上限 | 任意 | 要求拆分文件，或转异步任务返回任务号 |
| 对方系统定时拉取 | 任意 | 提供带游标的批量接口，不做文件传输 |

> 判定顺序：先估行数与耗时，再看用户能不能等，最后才决定同步还是异步。

## Step 2 · 流式读写的形状

- 读：按行迭代，单行解析失败记录行号后继续；禁止整本载入内存
- 写：边取数边写输出流，每批固定条数（几百到一千行）刷一次
- 分批取数用游标或主键区间，不用大偏移翻页
- 生成前把单元格格式定成文本或数字，避免长数字被转成科学计数
- 行列上限、列宽在生成时校验，超限显式报错而不是静默截断

## Step 3 · 导入校验与部分失败

- 三层校验：表头与版本 → 单行字段（类型、长度、枚举）→ 跨行与跨表（唯一、引用存在）
- 错误报告含行号、列名、原值、原因，使用者能直接照着改
- 整批回滚：全量校验通过才开始写库，写库本身在一个事务或一个批次里
- 部分成功：每批一个事务，失败行跳过并汇总，返回成功数、失败数与报告文件
- 跨行唯一性先在内存或临时表里查，不能边写边查库

## Step 4 · 大文件与清理

- 超过阈值要求用户拆分，或服务端分片解析后合并结果
- 临时文件放约定目录，文件名带业务键与时间戳，便于定位与清理
- 导出文件设过期时间，定时任务清理超期文件
- 进程被杀这类异常退出，靠定时任务扫孤儿文件，不能只靠 finally
- 下载接口做权限校验，不能凭文件名可猜就放行

## 自检清单

- [ ] 表头或版本不符时整体拒绝，并提示缺哪一列
- [ ] 错误报告含行号、列名、原值、原因
- [ ] 导入内存占用不随行数线性增长
- [ ] 导出边取边写，耗时与行数成正比且有明确上限
- [ ] 成功与失败路径都不残留临时文件
- [ ] 失败策略（整批回滚 / 部分成功）已写进入口文档
- [ ] 下载接口有权限校验，文件有效期已设置

## 常见错误

- 整本载入再逐行处理 → 大文件直接把进程内存打满
- 失败只返回一句"导入失败" → 使用者无从修正，反复重试
- 先查全量再拼装导出 → 内存与耗时双双失控
- 长数字列没设文本格式 → 导入后精度丢失
- 只靠 finally 清理临时文件 → 进程被杀后文件长期残留
