harness-bootstrap · v1.27.0

把 AI 编码的约定
变成可执行的约束

Harness Bootstrap 是一个元技能。它读取一个真实项目，按证据生成 AGENTS.md、规则、技能、wiki 和模块卡，再装上一套 git 门禁、阶段门、字段校验和度量脚本。 装完之后，项目的约定由机器执行，人只确认关键决策。

61 条跨文件契约 10 个阶段门 3 个 git hook 2 条落地路径 E0–E4 证据分级
01

它是什么

先看边界，再决定要不要用

元技能，不是模板包

模板只是原料。安装时会探测项目事实，按证据改写或重建内容；大多数项目不会原样铺模板。

  • 技术栈、模块、命令来自 probe-project.ps1 / probe-stack.ps1
  • 项目断言必须有 E1（可跑命令）或 E2（真实文件 + 行号）
  • 无法确认的写 TODO(待确认)，不编造

交付物是机制

真正的产物不是一堆 md，而是能在提交时拦住违规的 hook、能在收尾时判定字段的脚本、能看趋势的度量。

  • pre-commit：红线 + SQL 评审 + summary 基础字段
  • stage-gate：10 个阶段，AUTO 真跑命令
  • metrics：纠正次数、拦截数、绕过率、技能加载率

两条落地路径

存量项目先取证再生成；新项目先确认背景、业务和选型，再生成骨架。两者用同一套接地协议。

  • 存量：E1 / E2 证据
  • 新项目：E0 用户确认（仅无代码阶段）
  • 代码落地后，E0 必须升级为 E1 / E2
适合不适合
已经有代码、想给 AI 编码加约束的存量项目只想复制一套现成模板、不愿做项目取证的场景
刚启动、愿意先确认业务和选型的新项目要求“AI 写出完美代码”的承诺
Windows + PowerShell 5.1 为主，或愿意按平台适配完全不愿改 git hook / 提交流程的团队

2

让智能体执行 SKILL.md 第 0 步

先探测平台和项目事实，再走两条路径之一。复制语义是 Copy-Missing：只补缺失文件，已存在的列 [SKIP] conflict，绝不覆盖；.gitignore 也只在缺失时复制。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\probe-project.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\probe-stack.ps1
3

安装 git 门禁

安装 pre-commit、post-commit、pre-merge-commit。已有 hook 会先备份为 .bak-harness；linked worktree 下用 git rev-parse --git-path hooks 定位真正生效的目录。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install-git-hooks.ps1
4

验收结构

三个脚本都要 0 FAIL。它们只证明结构和证据真实，不证明“效果已经达到”。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-harness.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-grounding.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stage-gate.ps1 -Stage 7 -Feature <name>
5

升级已有项目（不是重装）

第 0 步是 Copy-Missing，重跑不会更新旧脚本。升级替换 scripts\*.ps1 / *.py，保留 JSON 配置、项目资产与历史；旧文件备份到 .harness\upgrade\。-MergeSkills 以新模板为骨架、只保留 harness:project 区块，并按 frontmatter name 匹配改名目录；-UpdateSkills 只替换仍含 slot: 的未编译技能，已编译技能保持 MANUAL（-ForceSkills 才强制覆盖；它会把技能重置为骨架，需重新编译后再跑 verify-harness.ps1，重置步骤用 -SkipVerify）。升级默认重装 git hook。完整规则见第 6 节。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\update-harness.ps1 -PackagePath <新包根目录> -MergeSkills
# 确认差异后
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\update-harness.ps1 -PackagePath <新包根目录> -Apply -MergeSkills
新项目不是“跳过取证”。 它要求先完成五轮确认（背景、业务边界、架构、技术选型、验收口径）， 把结论写进 .harness/project-brief.md，带确认人和 YYYY-MM-DD 日期。 这个日期是 E0 合法的机器判据；代码落地后必须升级为 E1 / E2。

日常使用

一个任务从进入到收尾
层读什么什么时候进上下文
常驻AGENTS.md：技术栈、必跑命令、红线、文件索引、必上技能每轮都在（≤150 行）
触发已装技能的 name + description（平台只按这两个匹配）清单每轮在场，命中当前任务才加载正文
引用技能正文指到的 rules/、wiki/、modules/正文让你读时才读

一个任务不会把全部规范塞进上下文：先按 AGENTS.md 的索引找到该加载哪个技能，再由 description 匹配当前任务，最后只读技能正文指向的那几份文件。加载情况写进 summary.md 的 loaded_skills，metrics.ps1 据此计算加载率；平台没有自动发现能力时，退化为 .harness/skills/README.md 索引 + 常驻文件里的必读清单。

十个阶段；标 AUTO 的判据由脚本判定，HUMAN 只提示不阻断。

任务开始

收到需求先加载 request-analysis，建立 .harness/changes/<feature>/summary.md，写清需求、验收、影响面、风险和任务拆分。

powershell -NoProfile -ExecutionPolicy Bypass \
  -File scripts\stage-gate.ps1 -Stage 1 -Feature <name>

动代码

先加载 coding-skill；改完必须真跑 AGENTS.md 里的编译 / 测试命令。阶段 3 和阶段 5 会再次执行同一条命令，不通过就 BLOCKED。

powershell -NoProfile -ExecutionPolicy Bypass \
  -File scripts\stage-gate.ps1 -Stage 3 -Feature <name>

合并前

加载 expert-reviewer，把结论写进「评审结论」和「待补短板」。L2 / L3 合并前跑阶段 7；L1 仍需正常合并，只是不跑这道阶段门。

powershell -NoProfile -ExecutionPolicy Bypass \
  -File scripts\stage-gate.ps1 -Stage 7 -Feature <name>

收尾

阶段 10 校验收尾字段：lesson_id（同一条教训复用同一个 id）与 sql_review（有 SQL 必评审）。缺字段或留占位符 = 任务未完成。

powershell -NoProfile -ExecutionPolicy Bypass \
  -File scripts\stage-gate.ps1 -Stage 10 -Feature <name>

阶段门的三态

状态触发条件行为
PASS命令存在、已实测、退出码 0该判据通过
SKIP行存在，但仍是占位符或标了「待实测 / 不适用」不阻断，也不假装通过；交付说明必须点名
BLOCKED整行缺失，或真跑退出码非 0禁止进入下一阶段，先修 FAIL 行

summary 字段分两档

字段阶段 1 / pre-commit阶段 10
loaded_skills / load_skip_reason必填保留
flow / corrections / impl_corrections / touched_modules必填保留
lesson_id不查（WIP 提交不骚扰）必填；corrections ≥ 1 时必须是真实 kebab-case id，无教训写 -
sql_review不查必填；无 SQL 写「无 SQL 变更」
04

内部工作机制

三层职责 + 三处拦截

.harness/ · 知识真源

规则、技能正文、wiki、模块卡、变更记录。这里没有任何平台语义，只靠路径被引用。

  • 规则：不可协商的边界
  • 技能：按需加载的具体做法
  • wiki / 模块卡：项目事实与位置知识

.trae/ · 平台入口

技能链接、子智能体、门禁配置。平台的自动发现从这里读取，换工具时只改链接。

  • skills：指向 .harness/skills
  • agents：评审 / 一致性 / 红线审计
  • Claude 对应 .claude/

scripts/ · 机制

探测、扫描、阶段门、字段校验、度量、卸载。门禁不依赖编辑器，只依赖 git。

  • probe-*：只读探测
  • red-line-scan：只扫新增行
  • stage-gate / check-summary / metrics

三层约束力

层内容载体约束力
常驻技术栈、红线、文件索引、编码纪律AGENTS.md（≤150 行）参考
按需规范细节、专项技能、项目事实.harness/skills / wiki / modules参考
强制红线扫描、字段校验、阶段门scripts/ + git hook强制

门禁到底怎么拦

pre-commit

  • 只读 git diff --cached（staged diff）
  • 红线扫描只覆盖新增行，存量违规不阻塞
  • 有 SQL 规则时，staged diff 含 SQL 就必须带 sql_review 结论
  • summary 只查基础字段；-Stage initial
  • 扫描器 / 运行时 / diff 生成失败 → fail-closed

post-commit + pre-merge-commit

  • post-commit 记录本次提交是否被门禁覆盖（scanned: 1/0）
  • metrics 用 scanned: 0 计算绕过率
  • 合并提交不触发 pre-commit，由 pre-merge-commit 接管
  • 阶段 4 / 7 的 gate-proven 同时要求两个 hook 带安装标记
hook 目录不是硬编码的。 所有脚本统一用 git rev-parse --git-path hooks： linked worktree 下不会写进永不执行的 .git/worktrees/<name>/hooks， core.hooksPath 被设置时也会落到真正生效的目录。

证据分级：什么能进技能正文

级别定义能否进正文
E0用户确认：带确认人和 YYYY-MM-DD仅新项目无代码阶段；有代码后必须升级
E1机器可验证：跑得通的命令、脚本输出、测试结果直接引用
E2代码事实：真实文件 + 行号直接引用
E3文档陈述：README、注释、他人口述标注来源，不算已验证
E4推断：从命名、结构、经验推出来只能进 TODO(待确认)

判定分三种：没有 project-brief.md 出现 E0 → FAIL；有 brief 但代码未落地 → E0 合法； 有 brief 且源码已有真实文件 → E0 只报 WARN 要求升级，第一个真实任务必须把它换成 E1 / E2。

这个包怎么检查自己

tools/verify-package.ps1 是包级唯一入口，检查：

  • parse：所有 .ps1 能被 PS 5.1 解析
  • encoding：无 BOM 的 .ps1 必须纯 ASCII；有 BOM 才允许中文
  • json：所有 JSON 可解析
  • version：VERSION 与 releases.json 顶部版本一致
  • structure：必需文件存在，仅本包文件不存在于项目分发包
  • contract：61 条「同一规则必须同一写法」的跨文件断言
  • smoke：临时副本安装 → 阶段 4 → 未填 summary 被拒 → 卸载

提交时 pre-commit 自动跑 -Fast（跳过 smoke）；发布前跑全量。

度量与成长

从一次任务到项目趋势

教训不是靠记忆，而是靠计数触发晋升。

Loading...

任务级 A6

corrections ≤ 2 且 impl_corrections: 0。实现细节的纠正应该是 0；如果人一直在纠正实现层，说明规则或技能没落地。

项目级 A6

metrics.ps1 -Days 14 -Compare 比较两个连续 14 天窗口，趋势不能是 REGRESSING。不足 28 天历史时输出 INSUFFICIENT DATA，不下结论。

A7 闭环

同一个 lesson_id 第 2 次出现时，脚本直接提示晋升。模板层面的回灌还要求两个独立项目都踩过，避免把单个项目的偶然问题带进模板。

反作弊信号

bypassRate 来自 post-commit 的 scanned: 0。人纠正变少但 blocked 一直是 0，通常说明门禁没装或已被绕过，不是真的变好。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts\metrics.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\metrics.ps1 -Days 14
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\metrics.ps1 -Days 14 -Compare -Json

升级

已装项目怎么换机制

重跑 SKILL.md 第 0 步不会更新旧脚本：Copy-Missing 只补缺失文件。 升级要用 scripts\update-harness.ps1；默认只打印计划，加 -Apply 才执行。

先看计划，再执行；MANUAL 项不会被自动改写。

旧文件与新文件怎么处理

对象动作旧文件
scripts\*.ps1缺失 ADD；不同 UPDATE先备份到 .harness\upgrade\<时间戳>\，再替换
scripts\*.json缺失 ADD；不同 MANUAL不覆盖；红线、阈值、必查文件属于项目配置
scripts\*.py缺失 ADD；不同 UPDATE与 .ps1 一样先备份再替换
.harness\rules / wiki / modules只补缺失已存在 SKIP，项目资产不动
.harness\changes只补 _template真实变更记录 KEEP，永不触碰
.harness\metricsKEEP门禁日志与晋升记录不动
AGENTS.md缺失 ADD；相同 SAME；不同 MANUAL永不覆盖，按新包 diff 手工加行/段落
.trae\agents / .claude\agents缺失 ADD；相同 SAME；不同 MANUAL你改过的评审智能体不覆盖
.gitignore缺失 ADD；同时有 .harness/metrics/ 与 .harness/upgrade/ 则 SAME；否则 MANUAL不重写，手工补行
.harness\skillsREADME 是项目索引，不同 → MANUAL；已装技能不同 → MANUAL；-MergeSkills 用新模板骨架替换通用段、只保留 harness:project 区块（frontmatter 保留，项目独有区块追加），按 frontmatter name 匹配改名目录（04-sql-review ↔ 14-sql-review），定位不到或仍有 slot → PENDING，超 120 行 → MANUAL，均不写盘；-UpdateSkills 只替换含 slot: 的未编译副本；-ForceSkills 才强制覆盖默认保留；未安装的模板技能不会新增；已编译事实不被覆盖
.trae\skills\harness-bootstrap不在计划手动替换技能包副本
git hooks重装旧 hook 自动备份为 .bak-harness
.harness\.installed-version写入下一次升级据此识别旧版本

会变

  • scripts\*.ps1 换成新版，旧版在 .harness\upgrade\ 可回滚
  • 三个 git hook 换成新版
  • 阶段 3 / 5 / 7 / 8 开始真跑 AGENTS.md 命令
  • 缺行 BLOCKED、占位 SKIP、退出码非 0 BLOCKED

不会变

  • .harness\changes 任务历史
  • .harness\metrics 门禁与晋升记录
  • 已存在的规则、wiki、模块卡
  • AGENTS.md 正文（除非你手工合并）
  • 项目自定义的 JSON 配置
升级后第一件事：补齐 AGENTS.md 的「必跑命令」表。 阶段 3 / 5 会真跑这些命令；缺行会 BLOCKED，占位会 SKIP，不是回归，是新机制在生效。
升级后第二次验证：跑 verify-harness.ps1。两类 FAIL 属于预期： gate（旧 hook 早于 summary-order guard，升级默认已重装；用 -SkipHooks 才会保留）与 skills-registry（项目里存在但没登记或没入口的技能，按提示补 skills/README.md 与平台入口）。 -MergeSkills 报 PENDING 的技能，通常是编译时改过小节标题（如把「项目绑定」写成「本项目绑定」）， 改回模板标题或手工合并后再跑一次。
当前版本的行为： 没有 -DryRun 参数，默认就是 Dry-Run；-Apply 执行。 已装技能正文默认只报 MANUAL；-MergeSkills 以新模板为骨架，只把 harness:project 区块换回项目自己的（frontmatter 保留，项目独有区块追加；无法定位或仍有 slot 标 PENDING，超过 120 行标 MANUAL，均不写盘）； -UpdateSkills 只替换仍含 slot: 的未编译副本， 已编译技能需 -ForceSkills 才整体覆盖； 未安装的模板技能不会新增，安装时 3–5 个技能的策略保持不变。 .gitignore 需要同时包含 .harness/metrics/ 与 .harness/upgrade/，缺哪个就手工补。 -SkipHooks / -SkipVerify 仅排障时使用；脚本没有降级保护，不要指向旧包。

A1–A7 验收

#标准怎么验
A1先分析再动手真实跑一个需求，看是否先产出 summary.md
A2主动加载技能看它读了哪些文件
A3符合项目约定抽查 3 条改动，≥2 条能对应到规则条款
A3+该补的短板补上并说明「待补短板」有结论（“无”也算）
A4自己跑校验并贴真实输出看有没有贴命令结果
A5机器门禁能拦住违规提交故意造违规，提交必须被拦
A6人只确认关键决策任务级 + 项目级两层（见第 5 节）
A7同一个错误不犯第二次同一 lesson_id 出现 ≥ 2 次 → 必须晋升

verify-* 全绿只代表结构正确。A1–A4、A6 要靠跑真实任务；A7 需要两个连续 14 天窗口。
