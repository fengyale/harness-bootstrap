# 代码评审

> **本文件是骨架**：`<!-- slot:… -->` 必须在安装时用项目事实替换。

## 何时用

- 编码完成、准备合并
- 用户说"审一下 / review / 能不能上"

## 项目绑定（编译时替换）

- 项目红线清单：<!-- slot:redlines -->
- 本项目高发的额外检查项：<!-- slot:extra.checks -->
- 评审结论写回位置：<!-- slot:review.output -->

## 模式（跨技术栈不变）

| 维度 | 看什么 |
| --- | --- |
| 结构 | 是否落在正确模块与层（控制层不写业务） |
| 红线 | 项目红线逐条对照 |
| 性能 | 循环查库、无分页、大事务 |
| 安全 | SQL 拼接、敏感信息落日志 |
| 一致性 | 缓存与库更新顺序、跨模块调用 |
| 可测性 | 没有测试时，是否写清手工验证步骤 |

## 输出格式

- 🔴 阻断（红线未清零，禁止合并）：给 `文件:行`
- 🟡 建议（不阻断）：给理由与代价
- ✅ 通过：列出实际执行的检查项

## 常见错误

- 只写"看起来没问题" → 没有可复核的结论
- 把建议写成阻断，评审变成吵架
