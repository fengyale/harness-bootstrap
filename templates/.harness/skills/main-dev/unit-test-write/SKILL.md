## 模式（跨技术栈不变）

### 步骤

1. 先写期望行为：给定输入 → 可观察输出或副作用，再动手写实现
2. 一条用例只验证一个行为，绝不一条断言多个关注点
3. 覆盖边界：空、单元素、上限、超限、重复值
4. 覆盖异常路径：依赖失败、超时、非法输入、权限不足
5. 外部依赖（存储、网络、时钟、随机、随机数种子）一律打桩
6. 只断言可观察结果，不断言内部调用次序与私有细节
7. 跑全量确认无隐藏耦合，并记录真实通过情况而非声称通过

### 检查项

- [ ] 重构实现细节而不改行为时，用例仍应全部通过
- [ ] 每个分支至少有一条边界用例
- [ ] 失败提示能直接指出哪条期望不符
- [ ] 用例之间无顺序依赖，不依赖真实系统时间
- [ ] 全量测试耗时在可接受范围

### 常见错误

- 为凑覆盖率写无断言或只断言不失败的用例
- 断言内部方法被调用几次，实现一变就红
- 依赖共享状态或真实外部资源，导致偶发失败
