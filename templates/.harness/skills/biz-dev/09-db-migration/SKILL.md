# 数据库变更

> **本文件是骨架**：`<!-- slot:… -->` 必须在安装时用项目事实替换，替换不到就整条删除。

## 何时用

- 上线包含表结构变更或字段语义变更
- 需要给大表做数据订正，担心锁表与耗时
- 变更出问题需要回滚，但没准备反向脚本

- 回滚脚本的存放与执行命令：<!-- slot:rollback.cmd -->

## 模式（跨技术栈不变）

### 步骤

1. 写变更说明：目的、影响表、是否锁表、预计耗时、可回滚性
2. 脚本可重入：先判断存在性再执行，重复跑不报错
3. 每条正向变更配一条反向脚本，且反向脚本必须演练过
4. 大表拆步：先加可空列，再分批回填，最后才加约束
5. 排上线顺序：先让旧代码兼容新结构，代码与结构交错过渡
6. 在等价数据量的非生产环境演练，记录真实耗时
7. 上线后核对行数、抽样关键值，确认无静默截断

### 检查项

- [ ] 脚本重复执行结果一致且不报错
- [ ] 每条变更都有对应回滚脚本且已执行过一遍
- [ ] 大表变更的实际耗时已测，不靠估算
- [ ] 发布顺序在变更说明里写明
- [ ] 演练环境数据量级与生产可比

### 常见错误

- 直接改列类型或加非空约束，触发全表重写与长锁
- 回滚脚本最后补写，从未被执行验证
- 先删旧列，导致仍在运行的旧版本代码报错
