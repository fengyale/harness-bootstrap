# 文件上传

> **本文件是骨架**：`<!-- slot:… -->` 必须在安装时用项目事实替换，替换不到就整条删除。

## 何时用

- 新增文件上传能力，需要控制类型与体积
- 已上传文件被直接暴露为可猜路径
- 上传失败或超时后残留大量孤儿文件

## 模式（跨技术栈不变）

### 步骤

1. 定白名单：允许的类型按内容特征判定，不只看扩展名
2. 定体积上限，服务端在读取前就拒绝超限请求
3. 存储用不可猜的对象键，原始文件名只作为展示字段
4. 访问与存储分离：下载走受控接口或限时链接，目录不做静态暴露
5. 先落临时区，业务确认后再转正，未转正的定时清理
6. 大文件分片上传以内容摘要作幂等键，重试不产生多份
7. 检测不通过时删除已落盘内容，避免残留可访问文件

### 检查项

- [ ] 伪装扩展名的文件被拒绝
- [ ] 超限请求在读取阶段即被拒，不落盘
- [ ] 访问链接有有效期或需鉴权，路径不可枚举
- [ ] 孤儿文件有清理策略并在运行
- [ ] 同一文件重复上传不产生多份存储

### 常见错误

- 只用扩展名判断类型，可执行内容被放行
- 上传目录直接对外提供静态访问
- 失败或中断时残留半份文件，长期占空间
