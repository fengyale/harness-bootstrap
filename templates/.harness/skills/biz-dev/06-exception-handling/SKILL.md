# 统一异常处理

> **本文件是骨架**：`<!-- slot:… -->` 必须在安装时用项目事实替换，替换不到就整条删除。

## 何时用

- 新增一组接口，需要统一的成功与失败返回形状
- 现有接口报错五花八门，前端无法按码分支处理
- 线上问题需要从用户描述对应到具体一次请求

## 模式（跨技术栈不变）

### 步骤

1. 先分类：参数非法、业务规则不允许、依赖不可用、未知系统错误，四类不混
2. 每类分配独立错误码区间，码一经发布不复用、不改语义
3. 定义对外消息：面向使用者可读，不含堆栈、语句、内部主机与路径
4. 内部保留完整上下文：请求标识、关键入参摘要、错误链，只落日志不外传
5. 在统一出口做一次转换，禁止各层各自拼返回体
6. 兜底覆盖未预期错误，避免默认错误页泄漏实现细节
7. 用一次真实失败请求验证：前端拿到的码、话术与日志标识能对上

### 检查项

- [ ] 每个对外错误码在字典里有唯一含义与归属类别
- [ ] 任何返回体都不含堆栈、内部地址、表名或语句
- [ ] 同一请求的日志可用链路标识串起来
- [ ] 未捕获错误与已知错误的返回形状一致
- [ ] 敏感入参在日志里已脱敏

### 常见错误

- 业务层抛出带内部信息的消息，被原样返回给调用方
- 用同一错误码表达所有失败，前端只能靠文案猜分支
- 只记错误消息不记请求标识，事后无法定位是哪一次调用
