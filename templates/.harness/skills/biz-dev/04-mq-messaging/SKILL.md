# 消息生产与消费

## 何时用

- 主流程要解耦出异步动作（通知、统计、下游同步）
- 已有消费者出现重复处理、丢消息或无限重试
- 同一业务实体的多个事件必须按发生顺序被处理

## 模式（跨技术栈不变）

### 步骤

1. 先定事件契约：谁生产、谁消费、字段与版本，变更只增不改语义
2. 生产端确认：发送结果要能判定成功，与本地业务写入的一致性要有明确方案
3. 消费端幂等：以业务唯一键去重，重复投递结果与一次投递相同
4. 失败分级：可重试（瞬时依赖故障）与不可重试（数据非法）分开处理
5. 重试设上限与退避，超限进死信并落库，保留人工重放入口
6. 需要保序时用业务键路由到同一队列，且消费并发按该键串行
7. 上线后盯三件事：生产成功率、消费延迟、死信量

### 检查项

- [ ] 同一事件重复投递只产生一次业务效果
- [ ] 发送失败能被发现，而不是静默丢弃
- [ ] 死信有归宿、可查询、可重放
- [ ] 保序事件的键与消费并发设置匹配
- [ ] 契约变更时旧版本消费者仍能解析

### 常见错误

- 消费端先查再写，无唯一约束兜底，并发下仍然重复
- 无限重试毒消息，堵住队列里后面所有事件
- 靠全局并发消费还要保序，顺序实际不成立
