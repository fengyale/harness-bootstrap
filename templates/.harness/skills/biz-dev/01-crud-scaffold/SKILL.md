# 单表增删改查脚手架

> **本文件是骨架**：`<!-- slot:… -->` 必须在安装时用项目事实替换，替换不到就整条删除。

## 何时用

- 新业务表需要第一版可用的新增、编辑、详情、列表、删除能力
- 已有表缺管理端维护接口，且不希望逐个手写样板
- 需要交付一套字段、校验、错误提示口径一致的接口

## 模式（跨技术栈不变）

### 步骤

1. 先定字段清单：类型、可空、长度、取值枚举、默认值，一次写清再动手
2. 同一步定校验：必填、唯一、跨字段依赖，与字段清单落在同一份描述里
3. 分离写模型与读模型：写入只接受可写字段，读取按展示场景聚合
4. 实现列表：固定过滤条件、稳定排序、分页，禁止默认全量返回
5. 删除一律逻辑删除并保留可追溯标记，物理清理另设离线任务
6. 每个写操作留痕：操作者、时间、改前改后、来源渠道
7. 用一份真实样例数据跑通全部接口，再交给调用方联调

### 检查项

- [ ] 每个可写字段都能在字段清单里找到类型与约束
- [ ] 写入接口不会接受只读字段（主键、留痕字段、状态字段）
- [ ] 列表接口有默认排序，同样数据两次查询顺序一致
- [ ] 删除后详情与列表反映同一状态，且无物理删除路径
- [ ] 写入失败时不留半条记录与半份留痕

### 常见错误

- 先写代码后补校验，同一约束在入口、服务、存储三处口径不一
- 直接把存储结构当接口出入参，改表即破约
- 删除时顺带清理关联数据，缺事务边界导致部分成功
