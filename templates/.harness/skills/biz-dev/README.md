# biz-dev —— 业务开发技能集

> **职责**：具体实现——**这类代码怎么写**。
> 流程管控看 `main-dev`；线上排查看 `trouble-shooting`。

## 编号含义

**编号 = 技术专题**（不是执行顺序）。由 `main-dev/coding-skill` 按需引用，也可以单独使用。

## 13 个专题

| 编号 | 技能 | 什么时候用 | 关键约束 |
| --- | --- | --- | --- |
| 01 | `crud-scaffold` | 新增业务模块、做一套增删改查 | 生成顺序固定，禁止发明分层 |

| 03 | `redis-cache` | 给查询接口加缓存 | 🔴 Key 前缀 + TTL；挂库不影响业务 |

| 05 | `transaction-consistency` | 多表写入、跨服务一致性 | 🔴 事务必须声明 rollbackFor |
| 06 | `exception-handling` | 新增异常类型、设计错误码 | 🔴 统一异常体系 |
| 07 | `business-validation` | 接口校验、业务规则前置检查 | 格式注解、业务在 Service |
| 08 | `excel-import-export` | 批量导入导出、报表导出 | 流式 + 分批，禁止全量加载 |
| 09 | `db-migration` | 改表结构、加索引、批量修数据 | 🔴 迁移与回滚必须成对 |

| 13 | `stats-report` | 数据看板、统计报表 | 🔴 先定口径再写 SQL |

## 使用约定

1. **先判断该不该用**：不是所有查询都要缓存，不是所有异步都要 MQ。技能里的「核心规则」第一条通常就是判断标准。
2. **模式优先照抄项目已有的同类实现**（技能里写的代码是"语义模板"，形状以项目为准）。
3. **拿不准就只加载一个**：上下文加载有预算（规则 + wiki 合计 ≤3 个，**技能与模块卡不占此额度**）。
4. 某个专题**项目里根本用不到**（如没有 MQ、没有前端），**直接删掉那个技能目录**，不要留着占技能清单。

## 说明

> 本技能集是**骨架 + 通用规则**。每个技能里的代码模板需要按项目实际技术栈补全；
> `<…>` 占位符要换成真实路径/类名，不确定的标 `TODO(待确认)`。
