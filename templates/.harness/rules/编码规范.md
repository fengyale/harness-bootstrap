## 异常处理

- 🔴 **必须使用统一异常体系**（`<异常基类所在位置>`），禁止裸异常泄露到 API 层。
- 异常类型选用对照表：

| 场景 | 异常类型 |
| --- | --- |
| `<资源不存在>` | `<NotFoundException>` |
| `<参数不合法>` | `<ValidationException>` |
| `<状态冲突>` | `<ConflictException>` |
| `<未认证/未授权>` | `<AuthException>` |
| `<其它业务失败>` | `<BusinessException>` |

- 业务代码**只管抛异常**：不 try-catch 后返回错误码、不捕获后空处理、不只打印堆栈。
- 全局异常处理集中在一处（`<位置>`），统一转成响应结构并分级记日志。

## 日志规范

- 使用 `<日志门面>` + 占位符，**禁止字符串拼接**。
- 级别约定：业务异常 `warn`；未预期异常 `error`（**必须带堆栈**）；关键流程节点 `info`。
- 🔴 **禁止把密码、令牌、手机号完整值、身份证等写入日志。**
- 消息消费者入口**必须**打 `info` 记录业务主键，便于排查。

## 依赖注入与事务

- 🔴 **必须构造器注入**（`<如 @RequiredArgsConstructor + final>`），**禁止字段注入**（`<如 @Autowired>`）。
- 🔴 **`@Transactional` 必须声明回滚范围**（`<如 rollbackFor = Exception.class>`），禁止异常时静默提交。
- 只读操作使用只读事务（`<如 readOnly = true>`）。
- 接口与实现分离（`<如 service/ 放接口，service/impl/ 放实现>`）。
- 🔴 **禁止从请求参数取当前用户 ID**，必须从上下文取（防越权）。

**✅ 正确 / ❌ 错误对照**

```java
// ✅ 构造器注入 + 声明回滚范围 + 从上下文取用户
@Service
@RequiredArgsConstructor
public class OrderServiceImpl implements OrderService {
    private final OrderMapper orderMapper;          // final + 构造器注入

    @Override
    @Transactional(rollbackFor = Exception.class)   // 声明回滚范围
    public void cancel(Long orderId) {
        Long userId = UserContext.getUserId();      // 从上下文取，不信任入参
        Order order = orderMapper.selectById(orderId);
        if (!order.getUserId().equals(userId)) {
            throw new AuthException("无权操作他人订单");   // 统一异常体系
        }
        // ...
    }
}

// ❌ 字段注入 + 无回滚范围 + 从参数取 userId（越权入口）
@Service
public class OrderServiceImpl implements OrderService {
    @Autowired private OrderMapper orderMapper;     // 字段注入
    @Transactional                                  // 未声明 rollbackFor
    public void cancel(Long orderId, Long userId) { // 谁能传谁的 id
        // ...
    }
}
```

## 数据访问（Repository / Mapper）

- `<ORM 基础用法>`；自定义 SQL 写在 `<资源位置>`，**禁止在 Java 里拼接 SQL**。
- 复杂查询用条件构造器，**禁止硬编码字段名**；分页用 `<分页对象>`。
- 🔴 **XML 一律用参数占位符，禁止字符串替换写法**（注入风险）。

## 缓存（Redis）

- 🔴 **Key 必须有统一前缀**，格式：`<项目前缀>:<模块>:<业务>:<标识>`。
- 🔴 **必须设置 TTL**，禁止永久 Key（除非有明确理由并在本文登记）。
- 写操作后**删除**缓存，而不是更新缓存。
- 禁止 `KEYS` 命令，用 `SCAN` 替代。
- 读-改-写必须用原子命令或分布式锁，**禁止"先 get 再 set"**。
- 缓存不可用时业务必须能降级（**Redis 挂了不影响主流程**）。
- 👉 具体怎么写，看技能 `redis-cache`；本文只定义边界。

**✅ 正确 / ❌ 错误对照**

```java
// ✅ Key 有前缀 + 有 TTL + 写后删缓存 + 异常降级
public XxxVO get(Long id) {
    String key = CACHE_PREFIX + id;                    // 统一前缀常量
    try {
        XxxVO v = (XxxVO) redisTemplate.opsForValue().get(key);
        if (v != null) return v;
    } catch (Exception e) {
        log.warn("cache get failed, key={}", key, e);  // warn，且不阻断
    }
    XxxVO vo = loadFromDb(id);
    try {
        redisTemplate.opsForValue().set(key, vo, 30, TimeUnit.MINUTES);  // 有 TTL
    } catch (Exception e) {
        log.warn("cache set failed, key={}", key, e);
    }
    return vo;
}

// ❌ 裸字符串 Key + 永久缓存 + 先 get 再 set + 缓存异常抛出去
public void update(DTO dto) {
    doUpdate(dto);
    XxxVO old = (XxxVO) redisTemplate.opsForValue().get("user:" + dto.getId()); // 无前缀常量
    redisTemplate.opsForValue().set("user:" + dto.getId(), old);                 // 无 TTL + 更新而非删除
}
```

## 消息（MQ）

- 🔴 **消费者必须幂等**：重复消费不产生副作用（有幂等键 + 查重/去重表）。
- 生产者**必须处理发送失败**（记日志 + 补偿或告警），禁止静默吞掉。
- 消息体**必须带业务主键**（以及链路追踪 ID）。
- 命名：Topic `<项目前缀>-<模块>-<事件>`；消费组 `<项目前缀>-<模块>-<动作>-group`。
- 消费失败**抛异常交框架重试**，禁止 catch 后假装成功。

## 安全

- 认证信息由过滤器/中间件统一校验并写入上下文；业务代码不自行解析令牌。
- **涉及资源归属的接口必须校验所有权**（防水平越权）。
- 密码等敏感信息必须走统一加密服务。
- 管理端接口必须有角色校验。
