# 落地策略（决定这套东西能不能活过第一周）

> 生成顺序、默认启用集、渐进路径、增量操作。**读这份再动手，不要直接铺满。**

---

## 一、默认启用集（**不要一次上 25 个技能**）

技能清单每轮都占上下文。首次落地**只启用这些**：

| 优先级 | 技能 | 理由 |
| --- | --- | --- |
| **必上** | `main-dev/request-analysis` | 没有它，后面全是凭感觉写 |
| **必上** | `main-dev/coding-skill` | 编码阶段的主入口 |
| **必上** | `main-dev/expert-reviewer` | 唯一能挡住问题的软闸 |
| **按需要** | `biz-dev/03-redis-cache` 或 `01-crud-scaffold` | 挑**本项目最高频**的那一个专题 |
| **按需要** | `trouble-shooting/01-slow-sql` | 如果线上已经在为慢查询头疼 |

其余技能**先不建**（不是建了再禁用，而是**根本不建**）。
判断何时加的方法：**同一条纠正出现第 2 次，再加一个技能**（见 `维护与体检.md` 提示词 B）。

> 反过来说：**25 个技能全上，是"看起来很完整"的实际失败模式**。
> 首次目标不是覆盖全流程，而是"让用户看到一次它真的自动触发并帮上忙"。

## 二、存量项目渐进路径（**最重要的部分**）

存量项目最典型的死法：

> 第一次跑红线扫描 → 报出 **300 处**历史违规 → 用户崩溃 → 关掉门禁 → 整套废掉。

### 三阶段

**阶段 1 · 只拦新增（第 1–2 周）**

1. 先跑一次扫描，把**现有违规数记下来**，写进 `.harness/changes/_baseline-redlines.md`（就一个数字 + 时间，作为基线）。
2. 门禁**只对本次变更的文件**生效：
   - 在 git hook 里改成本次 diff 的文件清单再扫描
   - 或临时把扫描范围限定为 `git diff --name-only` 里的路径
3. 目标：**任何一次提交都不能再新增违规**。历史债不碰。

> 这一步必须做对。**"只拦新增"是唯一能让人接受门禁的方式。**

**阶段 2 · 分类还债（第 3–6 周）**

1. 把历史违规**按类型分组**（哪种红线最多？集中在哪些模块？）
2. 每周挑**一类**清（如"这周专治日志泄露敏感信息"）
3. 每清完一类，把该类红线**从基线里划掉**并放开为全量拦截

**阶段 3 · 全量门禁（第 7 周后）**

1. 基线归零 → 扫描范围恢复全量
2. 此时门禁才算真正"焊死"

### 基线没清零时的门禁写法

```powershell
# 只扫描本次改动涉及的文件（示例，按项目实际路径调整）
$changed = git diff --cached --name-only --diff-filter=ACM
if ($changed) {
    # 逐个文件跑规则，或把文件清单传给扫描脚本
    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\red-line-scan.ps1 -Files $changed
}
```

> `red-line-scan.ps1` 已原生支持 `-Files`（文件清单）与 `-FilesFromStdin`（从 stdin 逐行读），
> 但 **pre-commit 钩子实际传的是 `-DiffFile`（`git diff --cached` 的 unified diff）**——
> 因为只扫新增行必须知道行号，而 `--name-only` 只有文件名。手工补扫全文件时才用 `-Files`。
> 首次落地时先确认这两条路径在目标机器上真的跑通。

## 三、干预矩阵（**同一个问题，先选手段，再写内容**）

> 缺口来自同一个误判：**所有纠正都被写成了"规则"**。规则最弱（靠自觉），
> 门禁最强（不做就过不去），但门禁只在**能机器判定**时成立。
> 下手之前先按"频率 × 代价 × 可判定性"选手段，选错手段 = 白写。

| 频率 | 代价 | 可机器判定 | 首选手段 | 不要用 |
| --- | --- | --- | --- | --- |
| 高频 | 高（钱/数据/安全） | ✅ | **门禁（fail-closed）** + 红线编号 + 扫描规则 | 只写进文档 |
| 高频 | 低 | ✅ | **lint 检查（警告级，不阻断提交）** | 写成红线口号 |
| 高频 | 任意 | ❌ | **技能**（按需加载）+ 审查清单 | 硬塞进 AGENTS.md（每轮占上下文） |
| 偶发 | 高 | ✅ | **红线 + 门禁** + 人工确认点 | 只靠评审智能体 |
| 偶发 | 高 | ❌ | **HUMAN 判据（stage-gate）+ 评审智能体** | 假装能脚本化 |
| 偶发 | 低 | 任意 | **模块卡 / wiki 记一笔** | 为它建一个技能 |
| 只出现过一次 | 任意 | 任意 | **只在 `summary.md` 记 `lesson_id`** | 立刻立规则 |

### 值得上机制的信号

- 同一条 `lesson_id` 在两个任务里出现过（`metrics.ps1` 会直接点名）
- 同一类提交被门禁拦下 ≥ 2 次（说明规则有效，值得细化）
- 用户在同一类问题上纠正 ≥ 2 次（说明"靠自觉"这条路已经失败）

### 不值得上机制的清单（**写了也是负债**）

- **只出现过一次的错误**：先在 `summary.md` 记 `lesson_id`，等同一 id 第二次出现再晋升成规则 / 门禁 / 技能
  （晋升完成后把该 id 追加进 `.harness/metrics/promoted.txt`，`metrics.ps1` 就不再重复提醒；这个文件是"已晋升清单"，不是待办队列）
- **编译器 / 类型系统已经能抓的**：不要重复包装成扫描规则
- **纯风格偏好**（命名偏好、空行数量）：写进技能示例即可，不要做扫描器
- **需要业务判断的取舍**（红线松紧、要不要补短板）：只能做确认点，不能做门禁
- **团队还没达成共识的规范**：先讨论，别急着落盘成红线
- **只影响单个文件的一次性约定**：写进那次任务的 summary，不进常驻层

> 一句话：**能机器判定的做成闸门，不能判定的做成技能或确认点，只出现一次的只做记录。**

## 四、首周该做的事（按天）

| 天 | 做什么 | 验收 |
| --- | --- | --- |
| D1 | 跑 `probe-project.ps1` 出基线 → 和用户确认技术栈与命令 | `baseline.md` 里没有"猜"的内容 |
| D1 | 建 `AGENTS.md`（薄）+ 3 个必上技能 + 1 个最高频 biz 技能 | `verify-harness.ps1` 无 FAIL |
| D2 | 开 AGENTS.md 开关 → 重启 → **验证技能真的自动触发** | 用一句话触发成功 |
| D3 | 用一次真实任务跑一遍流程（从需求分析到评审） | 用户说"这次没怎么纠正它" |
| D4 | 装 git 门禁（**只拦新增**模式） | 故意造违规 → 提交被拦 |
| D5–D7 | 再跑 2–3 个真实任务，每次做完执行"沉淀"提示词 | 技能/红线有增长，且都是真需求 |

**D2 那一步最关键**：如果技能没触发成功，后面全是自欺。**先证明机制通，再谈覆盖。**

## 五、增量操作入口（不用每次动全套）

| 用户说 | 只做这个 |
| --- | --- |
| "加一条红线" | 挑一条候选 → 三处同步 → 手工试跑 pattern → 确认无误报 |
| "补一个技能" | 只建那一个目录 + `SKILL.md` → 跑 `setup-links` → 登记索引 |
| "这次任务学到一条" | 走「沉淀」提示词 → 判断进哪一层（AGENTS.md / 技能 / 门禁） |
| "规则和代码不一致了" | 跑 `consistency-verifier` 智能体，只修文档不碰代码 |
| "技能太多了" | 走「技能体检」，删长期不触发与失真的 |
| "不想用了" | 跑 `uninstall-harness.ps1` |

**所有增量操作都不需要重跑完整落地流程。**

## 六、判断"这套东西到底有没有用"的四个信号

1. **你纠正它的次数在下降**（每周记一次，最直接的指标）
2. **红线扫描真的拦下过提交**（从没拦下过 = 太松或没生效）
3. **技能真的被自动触发过**（不是每次都要手动点名）
4. **改完一个技能你知道它是变好还是变坏**（说明体检在做）

**一个反信号**：技能越攒越多、谁也不敢删 → 体检没做，库在腐化。

---

## 七、最后的提醒

这套东西**不是装上就完事**。它更像"给项目装了一套仪表 + 几个闸门"：

- 规则（`AGENTS.md` / `rules/`）：**仪表**——让人和模型都看得见标准
- 技能（`skills/`）：**操作手册**——到了具体场景知道怎么做
- 门禁（`scripts/` + git hook）：**闸门**——不过就过不去

**只有仪表没有闸门 = 装饰品。只有闸门没有仪表 = 拦了不知道为什么。**
三者齐了，你才真的可以"少纠正、少检查、派活就走"。
