# 踩坑清单（实测踩出来的）

> 遇到"平台行为和预期不符"时读这份。全部在 Windows + PowerShell 5.1 + TRAE 上实测过。

## 一、本机环境（**最容易卡住，先看这里**）

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 执行策略拦未签名脚本 | 直接 `& xxx.ps1` 报「未对文件进行数字签名，无法在当前系统上运行」 | 一律用 `powershell -NoProfile -ExecutionPolicy Bypass -File xxx.ps1`。`CurrentUser = RemoteSigned` 会拦下载来源的脚本 |
| **PS 5.1 读 `.ps1` 只认「UTF-8 带 BOM」** | 脚本里写中文 → 报一堆莫名其妙的语法错误（`Unexpected token`、字符串没结束） | **`.ps1` 保持纯 ASCII**；中文放 JSON（脚本用 `Get-Content -Encoding UTF8` 显式读）。非要在 .ps1 里写中文，就另存为「UTF-8 带 BOM」 |
| 没有 `pwsh` | `pwsh` 命令不存在 | 用 `powershell`（5.1）。装了 PS 7 后两者皆可 |
| 路径含中文/括号 | — | 命令里一律用引号包住路径：`-LiteralPath "D:\项目\带 空格 的路径"` |

## 二、TRAE 平台侧

| 坑 | 说明 | 处理 |
| --- | --- | --- |
| `AGENTS.md` 不生效 | **必须手动打开开关**：设置 > 规则 > 导入设置 > 「将 AGENTS.md 包含在上下文中」；仅桌面版支持 | 交付时明确告诉用户 |
| `.trae/rules/` 是**全量加载** | 放进去的东西每轮都占上下文 | **绝对不要把技能塞进 `.trae/rules/`**，技能只放 `.trae/skills/` |
| `.trae/skills/` **只扫一层** | 技能目录必须直接躺在它下面，嵌套的不算技能 | 技能名全局唯一；每个技能一个联接 |
| 技能清单**每轮都占上下文** | 只有正文是按需的 | 技能别写太多；`description` 短且不撞词 |
| 目录联接**不跟 git 走** | 新机器 / 新 clone 后入口全没了 | 跑 `setup-links.ps1`；`.trae/skills/` 加进 `.gitignore` |
| 改完规则不生效 | 旧上下文和新规则打架 | **开新对话** |
| 模型沿用旧风格 | 项目里已有很多不合规代码时，它会"入乡随俗" | 明确告诉它"**这是重构**，严格按新规则" |

## 三、平台限制导致的"文档触发不可靠"

如果哪个工具**不支持原生技能**（只认全量规则文件），那"技能矩阵"会退化成"一个巨大的规则文件"。这时的替代方案：

- 用**根 `AGENTS.md` 的索引表** + 在技能正文里写**显式路径引用**，让模型自己去读（这是参考项目里 Claude Code 场景下的实际做法）
- **代价**：触发变成"软"的——索引表让模型知道有这个东西，但读不读、什么时候读，靠它自己判断
- **所以**：路径必须准确（含大小写），且索引表要写"**什么时候必须读它**"，不能只写路径

## 四、脚本与门禁

| 坑 | 说明 | 处理 |
| --- | --- | --- |
| 规则表写在脚本里写中文 | 触发上面那条编码坑 | 规则表放 `red-line-rules.json`（UTF-8），脚本纯 ASCII |
| 变量名大小写 | **PowerShell 变量名不区分大小写**：`$Rules` 参数会被 `$rules = ...` 覆盖，导致"规则总是空的" | 参数名与内部变量名必须真正不同（如内部用 `$ruleSet`） |
| 误报 | 规范文档里本身就含 `BigDecimal`、`RuntimeException` 这类反面示例 | 扫描默认排除 `.harness` / `.trae`；用 `requireAlso` 压误报 |
| hook 命令没跑通就挂上去 | 等于给自己装了个随机失败的提交按钮 | **先在终端手工跑通**，再挂 hook |
| 沙箱里测不了 git hook | 沙箱会拦 `sh.exe` 建管道，hook 里那步跑不完整 | 本地按脚本输出的 3 步自查：造违规 → commit 应被拦 → 删掉 → 应通过 |

## 五、内容维护

| 坑 | 说明 |
| --- | --- |
| 文档漂移 | 与代码不一致的规范**比没有更坏**（会自信地教错）→ 每份 wiki 声明权威来源 + 用 `consistency-verifier` 定期核对 |
| 技能只增不减 | 长期不触发 / 与代码不符的技能要**删**（见 `维护与体检.md`） |
| 验收标准不可判定 | "体验良好""代码优雅"这类词会让整套校验失效 → 一律改成可验证描述 |
