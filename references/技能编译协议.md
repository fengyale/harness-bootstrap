# 技能编译协议（Skill Compilation）

> **一句话**：模板技能只提供**骨架**；安装时必须用项目证据把正文"编译"成这个项目的技能。
> 编译不是"复制 + 尾部追加"，那样正文会和项目技术栈打架。

---

## 1. 三层结构

| 层 | 内容 | 是否随项目变 |
| --- | --- | --- |
| **模式** | 何时用 / 判断条件 / 步骤 / 检查项 / 常见错误 | 不变（跨技术栈、跨版本成立） |
| **绑定** | 类名、API、命令、目录、配置 | **必变**，必须来自证据 |
| **锚点** | `- [E1] cmd: …` / `- [E2] path#Lx-Ly :: …` | 每条绑定都要有 |

判断标准：**能从这个项目的代码里换出来的，是绑定；换不出来的，是模式。**

---

## 2. 四个动作

| 动作 | 规则 | 不合格 |
| --- | --- | --- |
| **留** | 五段骨架保留 | 缺段 |
| **换** | 具体类名/API/命令换成项目真实存在的 | 正文出现项目没有的技术名词 |
| **删** | 项目不存在的能力，整节删除（不留 TODO） | 留着就是噪音 |
| **加** | 项目特有的坑（来自真实结构或事故），带 E2 锚点 | 加不出却不标 `[E4]` |

---

## 3. slot 语法

模板正文里用 HTML 注释标记绑定点，编译后必须全部消失：

```markdown
## 步骤
1. 通过 <!-- slot:cache.api --> 读写缓存
2. key 由 <!-- slot:cache.key --> 统一拼接
```

校验：技能里再出现 `<!-- slot:` → **FAIL**。

---

## 3.1 区块标记（安装落盘，升级可合并）

模板技能里有两类内容，必须用 HTML 注释显式分开：

| 标记 | 归属 | 编译时 | 升级时 |
| --- | --- | --- | --- |
| `<!-- harness:package:begin <id> -->` … `<!-- harness:package:end -->` | 包（通用模式） | 原样保留 | **整体换成新版** |
| `<!-- harness:project:begin <id> -->` … `<!-- harness:project:end -->` | 项目（绑定 / 锚点） | 填 slot | **永不替换** |

规则：

1. `<id>` 必须匹配 `[a-z0-9][a-z0-9-]*`，同一文件内唯一；begin / end 必须成对，不允许嵌套或交叉。
2. `<!-- slot:` **只允许出现在 project 块内**；package 块里出现 slot → **FAIL**。通用段混进项目绑定，升级时会被抄进别的项目。
3. package 块里不许出现 `[E0]` / `[E1]` / `[E2]`：证据是项目事实，必须放 project 块。
4. 项目特有内容一律写进 project 块；写在块外的内容，升级时会被新版覆盖。
5. 新装：package 块原样落盘，project 块填 slot；升级：以新模板为骨架，只把 project 块换回项目自己的。

没有标记的老技能不报错：首次升级按“已编译技能”处理（MANUAL），重装或 `-ForceSkills` 后进入标记体系。

## 4. stack.json（编译输入）

`scripts\probe-stack.ps1` 产出 `.harness\stack.json`：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `language` / `buildTool` / `modules` | 语言、构建、模块数 | `java` / `maven` / `13` |
| `orm` | ORM 类型 | `jfinal` / `mybatis` / `jpa` / `null` |
| `cache` / `cacheApi` | 缓存与统一入口 | `redis` / `RedisUtils` |
| `mq` | 消息中间件 | `present` / `null` |
| `testFiles` | 测试文件数 | `2` |
| `frontend` | 前端框架 | `vue` / `react` / `null` |

编译前**必须先跑它**；没跑就没有"项目有什么"的判据。

---

## 5. 编译步骤

1. 跑 `probe-stack.ps1`，读 `stack.json`
2. 对每个启用的技能：读模板骨架 → 按四动作处理 → **每条绑定找 E1/E2**
3. **同时改写 `description`**：只写场景与能力，不写技术栈名（触发信号不能指向项目里不存在的东西）
4. 压到 **≤80 行**（**硬上限 120 行**，超过 `verify-grounding.ps1` 直接 FAIL），模式段占大头
5. 跑 `verify-grounding.ps1`：slot 残留、栈外名词、无锚点、行数超限、区块标记，五条都要绿

---

## 6. 五条机器校验（已实现）

| 校验 | 判定 | 说明 |
| --- | --- | --- |
| slot 残留 | FAIL | `<!-- slot:` 未填 |
| 栈外名词 | FAIL | 技能提到 `stack.json` 中不存在的能力；**带否定词的句子豁免**（"不要引入…"） |
| 无锚点 | WARN | 该技能没有任何 E1/E2，等于没接地 |
| 行数超限 | FAIL | 单文件 >120 行（目标 ≤80） |
| 区块标记 | FAIL | 未成对 / 嵌套 / id 重复；package 块内出现 slot 或 E0–E2 |

## 7. 反例 / 正例（redis-cache）

反例（复制模板）：

> 基于 Spring Data Redis 的 Cache-Aside 模板……`redisTemplate.opsForValue().set(key, value, 30, TimeUnit.MINUTES)`

正例（编译后）：

> 缓存读写统一走 `RedisUtils`；Key 由调用方拼好后传入；TTL 由调用方给。
> `- [E2] datasource/src/main/java/com/kyb/datasource/redis/RedisUtils.java`

差别不在文笔，在于**模型照着做会不会写错 API**。
