# 红线候选池（按技术栈分组）

> 用法：先读 `baseline.md` 确认技术栈，再**从对应分组里挑 5–8 条**落成本项目红线。
> **不要全选**——红线多了没人记得住，也会互相冲突。
> 选定后三处同步：根 `AGENTS.md` 的红线表、`.harness/rules/编码规范.md` 的红线汇总、`scripts/red-line-rules.json`。

## 挑选原则

1. **能机器判定**：给不出 grep/正则的，不是红线，是愿景。
2. **违反代价高**：金额错、数据错、安全事故、线上事故。
3. **本项目真的会犯**：从 `baseline` 的代码里看到苗头的优先。
4. **5–8 条**：超过就说明你没在取舍。

## 一、通用（任何技术栈都适用）

| # | 红线 | 建议检查动作（正则/搜索） | 建议规则 id |
| --- | --- | --- | --- |
| U1 | 敏感信息不得写入日志 | 日志调用行同时出现 `password\|passwd\|token\|secret\|身份证\|phone\|mobile` | R-log-secret |
| U2 | 不得提交密钥/凭据 | 扫 `*.env`、`*.pem`、`*.key`、`application*.yml` 里的明文 `secret\|password:` | R-no-secret |
| U3 | 异常不得静默吞掉 | 空 catch 块 `catch\s*\([^)]*\)\s*\{\s*\}` | R-empty-catch |
| U4 | 调试输出不得进入主分支 | `console\.log\|System\.out\.print\|print\(` 在非测试文件出现 | R-no-debug-print |
| U5 | 不得使用已废弃/危险 API | 项目维护的禁用清单（如 `eval(`、`exec(`、`pickle.loads`） | R-forbidden-api |

## 二、Java / Spring

| # | 红线 | 检查动作 | 备注 |
| --- | --- | --- | --- |
| J1 | 金额字段用整数最小单位 | `BigDecimal\|double\|float\|Double\|Float` 且同行含 `amount\|price\|money\|fee\|cents\|金额` | 需按项目确认是否真的全用分 |
| J2 | 禁止字段注入 | `@Autowired\s*\n?\s*private` | 构造器注入 |
| J3 | 事务必须声明回滚范围 | `@Transactional\s*\(\s*\)` | 缺 `rollbackFor` |
| J4 | 禁止裸异常泄露到 API 层 | `throw\s+new\s+(RuntimeException\|IllegalStateException\|IllegalArgumentException)` | 统一异常体系 |
| J5 | MQ 消费者必须幂等 | 人工审：`mq/consumer/` 逐个找幂等键 | 正则难判定，靠评审 |
| J6 | Redis Key 必须有前缀常量 | `opsForValue\(\)\.(get\|set)\(\s*"` | 裸字符串 Key |
| J7 | XML 禁止字符串替换占位 | `\$\{` in `*.xml` | `#{}` vs `${}` |
| J8 | 禁止从入参取当前用户 id | 方法签名含 `userId` 且来自请求体 | 防越权，靠评审 |
| J9 | 禁止物理删除 | `DELETE FROM` 在 mapper XML | 软删约定 |

## 三、Node / TypeScript / 前端

| # | 红线 | 检查动作 | 备注 |
| --- | --- | --- | --- |
| N1 | 禁止 `any` 泛滥 | `:\s*any\b` 计数超阈值即告警 | 可设为告警而非红线 |
| N2 | 金额不得用浮点运算 | `parseFloat\|toFixed` 出现在金额相关文件 | 用整数最小单位 |
| N3 | 禁止组件内直接用裸 HTTP 客户端 | `axios\.\|fetch\(` 出现在 `components/` `views/` | 必须走统一实例 |
| N4 | 禁止把令牌写进 localStorage | `localStorage\.setItem\([^)]*token` | 安全 |
| N5 | 禁止绕过类型检查 | `@ts-ignore\|@ts-nocheck\|as any` | 可设为红线 |
| N6 | 禁止在模板里做业务计算 | `views/` 里出现金额加减乘除 | 前端不做业务规则计算 |
| N7 | 依赖不得引入重复大包 | 人工审 `package.json` | 靠评审 |

## 四、Python

| # | 红线 | 检查动作 | 备注 |
| --- | --- | --- | --- |
| P1 | 禁止裸 `except:` | `except\s*:` | 吞异常 |
| P2 | 禁止 `eval` / `exec` / `pickle.loads` | 直接搜 | 反序列化/RCE 风险 |
| P3 | 金额不得用 float | 金额字段赋值出现 float 字面量 | 用 `Decimal` |
| P4 | 禁止 SQL 字符串拼接 | `execute\(\s*f"\|execute\(\s*".*%s.*"\s*%` | 参数化查询 |
| P5 | 禁止 hardcode 凭据 | `(password\|secret\|token)\s*=\s*['\"]` | 走环境变量 |

## 五、Go

| # | 红线 | 检查动作 | 备注 |
| --- | --- | --- | --- |
| G1 | 错误不得被忽略 | `_\s*=\s*\w+\(` 且函数返回 error | 靠评审 + linter |
| G2 | 金额不得用 float64 | 金额字段声明 `float64` | 用最小单位整数 |
| G3 | 禁止在 goroutine 里裸 `panic` | `go func` 内出现 `panic\(` | 会崩整个进程 |
| G4 | 禁止 SQL 字符串拼接 | `fmt.Sprintf.*SELECT\|DELETE\|UPDATE.*%s` | 注入 |

## 六、数据库 / SQL（跨栈）

| # | 红线 | 检查动作 |
| --- | --- | --- |
| D1 | 迁移必须有回滚 | `.harness/changes/*/db-migrations.sql` 存在时必须有 `rollback.sql` |
| D2 | 大表变更不得直接锁表 | DDL 中出现 `ALTER TABLE` 且无在线 DDL 说明 |
| D3 | 禁止 `SELECT *` 在生产查询 | `SELECT \* FROM` 在业务 SQL |
| D4 | 索引命名符合约定 | `idx_` / `uk_` 前缀 |

## 落地提示

- **首次只上 5 条**，优先挑"项目里已经能看到违规"的——第一次扫描就能抓到，用户才会信。
- 抓到很多历史违规时，**不要试图一次清零**，见 `落地策略.md` 的"存量项目渐进路径"。
- 每条红线的 `pattern` 要**先手工试跑**，确认不会误报一片再写进 `red-line-rules.json`。
