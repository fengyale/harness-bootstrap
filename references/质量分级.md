# 质量分级（哪些能直接信，哪些必须现场补）

> 目的：让 agent 和用户都清楚**每个文件的可信度**，避免把"骨架"当"成品"用。
> 打分口径：**A = 可直接用** / **B = 语义等价、需核对** / **C = 骨架待补**。
> 落地时必须把 C 级内容标记 `TODO(待确认)`，不许当成事实。

## 一、规则文件（`.harness/rules/`）

| --- | --- | --- |
| `编码规范.md` | **B** | 结构与"该管什么"是 A；具体约定（命名、注解、框架写法）是占位，必须按项目替换 |

## 二、技能（`.harness/skills/`，25 个 · 共 1245 行 · 平均 50 行）

> 所有技能都已补到"有实质内容"的级别：触发条件、核心规则、编号步骤、自检清单、红线齐全。
> 区别只在**代码模板的贴近度**——A 级贴近参考实现，B 级给的是通用可直接套用的模板。

| 级别 | 技能（数量） | 说明 |
| --- | --- | --- |
| **A**（按参考实现原文重写） | `03-redis-cache`（1） | 策略表、Cache-Aside 模板、穿透/击穿/雪崩、8 条自检、5 条红线完整 |
| **A−**（内容完整，代码示例为 Java 通用写法） | `01-crud-scaffold`、`04-mq-messaging`、`05-transaction-consistency`、`06-exception-handling`、`07-business-validation`、`09-db-migration`、`10-scheduled-task`、`unit-test-ci`（8） | 规则与流程可直接用；代码块需要按项目类名/包名替换 |
| **B**（语义等价，规则真实） | `main-dev/request-analysis`、`main-dev/expert-reviewer`、`main-dev/deploy-verify`、`main-dev/unit-test-write`、`main-dev/coding-skill`、`trouble-shooting/01-slow-sql`、`02-oom-troubleshoot`、`03-cpu-high-troubleshoot`、`04-mq-backlog-troubleshoot`、`05-redis-hotkey-troubleshoot`、`biz-dev/02-pagination-query`、`08-excel-import-export`、`11-file-upload`、`12-notification`、`13-stats-report`、`biz-dev/14-sql-review`（16） | 排查路径/校验顺序/口径要求这些**知识本身是对的**；具体命令与路径要按项目环境替换 |

**三级的实际含义：**

| 级别 | agent 拿到后要做什么 |
| --- | --- |
| A | 核对 Key 前缀等少数约定即可直接用 |
| A− | 把代码块里的类名/包名换成项目的，其余照抄 |
| B | 读一遍确认项目确实有这项能力，再按项目实际补命令与路径 |

> **重要**：即使是 B 级，也**不是空壳**——它已经告诉你"这里该有这件事、该按这个顺序做、该查这几项"，
> 这本身就消除了自由发挥的空间。剩下的"贴身适配"必须由落地 agent 用真实代码完成，
> **不能由模板代劳**（那会变成编造）。

> **升级路径**：某个技能被真实用到 N 次后，就该从 B 升到 A−：把项目里真实的那次实现提炼成模板。
> **已经安装但一直用不到的 B 级技能**：成本接近零（只在触发时加载正文），保留即可；
> 一旦 `metrics.ps1 -Days 28` 把它列为 `retire candidate`，按维护流程由人确认后再删。
> （"根本不建"针对的是首次落地；"保留 / 删除"针对的是已经装上的。）

## 六、落地时怎么用这张表

1. **A 级**：直接用，最多核对路径。
2. **B 级**：用之前**挑 2~3 条对照项目真实代码确认**（比如抽出 `redis-cache` 的 Key 前缀是否真是那个前缀）。
3. **C 级**：**逐份补全**，并把 `TODO(待确认)` 标出来。交付时如实告诉用户"这 N 个是骨架"。
4. **交付话术**：
   > "已生成 X 个文件；其中 A 级 N 个可直接用，B 级 M 个已核对，C 级 K 个是骨架需要你确认（清单见下）。"
   **不要笼统说"全部完成"。**

## 七、这张表怎么不漂移

数量、级别、脚本能力一旦变化，必须同步更新；否则这张表就从"可信度清单"变成"错误承诺"。

| 变化 | 必须同步 |
| --- | --- |
| 新增 / 删除技能 | 本文件第二节的「数量 · 总行数 · 平均行数」与分级表 |
| 新增 / 删除脚本 | 本文件第三节 + `scripts/harness-required.json` 的 `required` |
| 技能级别变化（如 B → A−） | 本文件 + `references/落地策略.md` 的默认启用集说明 |

> 数字要**重新数一遍**，不要按旧值加一：
>
> ```powershell
> $files = Get-ChildItem -Recurse -Filter SKILL.md -File
> "count=$($files.Count) lines=$(($files | ForEach-Object { ([IO.File]::ReadAllLines($_.FullName)).Count } | Measure-Object -Sum).Sum)"
> ```
